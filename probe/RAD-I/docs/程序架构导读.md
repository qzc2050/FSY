## 3. 程序启动流程

```
main.c
  └─ HAL/外设初始化
  └─ freertos_task()                    [FreeRTOS/APP/freertos_app.c]
       ├─ W25Q Flash 初始化
       ├─ W5500 硬件复位 + 默认网络配置
       ├─ set_w5500_network()           → DHCP 或静态 IP
       ├─ close(0); close(1);          → 关闭 TCP socket（后面会重开）
       ├─ Dev_Protocol_init()          → 注册 W5500/CAN/LoRa 协议设备
       └─ xTaskCreate(start_task) → vTaskStartScheduler()

start_task()
  ├─ flash_fs_mutex_init()
  ├─ HistRecord_Init()                 → 5 分钟历史数据管理
  ├─ DeviceConfig_Init()               → 探头配置读 Flash
  ├─ LORA_Init()
  └─ 创建各业务任务（见下节）
```

**注意**：`DHCP_Run()` 要等 `W5500_Task` 跑起来后才开始；`W5500_Task` 内有 `vTaskDelay(500)`，首包 DISCOVER 会偏晚。

| 任务 | 文件 | 优先级 | 主要职责 |
|------|------|--------|----------|

| `Geiger_Task` | freertos_app.c | 10 | 盖革计数、剂量率、阈值报警、蜂鸣器 |
| `Env_Monitor_Task` | freertos_app.c | 5 | 温湿压/CO2/PM2.5 采集、同步寄存器、触发 0x23 上传 |
| `LVGL_Task` | freertos_app.c | 10 | 屏幕 UI |
| `Uart_Recv_Task` | freertos_app.c | 5 | 串口命令解析（`cmd.c`） |
| `Key_Task` | freertos_app.c | 11 | 按键 |
| `ws2812_task` | freertos_app.c | 4 | 状态灯带 |
| `USB_Disk_Task` | freertos_app.c | 6 | USB MSC（默认关闭，代码里可注释掉创建） |

### W5500_Task 每轮（约 2ms）做什么

```c
DHCP_Client_Task();        // IP 获取 / 续租 / 链路恢复
DHCP_Watchdog_Task();      // 长时间无 IP → 硬复位 W5500
UDP_Broadcast_Task();      // 组播发现 236.2.3.6:2468
Net_Tcp_PeriodicMaintain(); // TCP listen 健康检查
Net_Thread_Task();         // Modbus 协议收发轮询
Ota_Thread_Task();         // OTA 超时 / 自动重启
```

## 5. 网络架构（重点）

### 5.1 总体模型

**不是 lwIP 软件协议栈**，而是：

```
业务应用 (net_raw_app.c)
    ↓ 寄存器 / 0x23主动上传 / OTA
协议中间件 (net_raw_protocol.c)  ← Modbus RTU 帧、CRC、队列
    ↓ Ph_Net_Transmit / Ph_Net_Receive
传输 BSP (net_raw_bsp.c)         ← W5500 / CAN / LoRa 抽象
    ↓
网络服务 (w5500_dhcp.c)          ← DHCP、UDP 组播发现
    ↓
W5500 驱动 (w5500.c, socket.c)   ← SPI + 硬件 Socket
    ↓
W5500 芯片（片内 TCP/UDP/IP）
```

### 5.2 协议框架三层句柄

定义在 `dev_protocol/net_raw/net_raw_protocol.h`：

| 类型 | 含义 | 本机实例 |
|------|------|----------|
| `Net_Ctrl_t` | 协议总控 | `netctrl`，`init = Net_Device_Init` |
| `Net_Periph_t` | 通信外设 | `net_w5500_ph`、`net_can_ph`、`net_lora_ph` |
| `Net_Device_t` | 从机设备实例 | `net_w5500_dh` 等，含寄存器表、收发队列 |

**发送链路优先级**：TCP > CAN > LoRa（`Net_TxInft_UpdateCrt`）

**协议调度入口**：`Net_Thread_Task()` → `Net_Transmit_Task` / `Net_Resolve_Task` → `Net_Resolve_Handle`

### 5.3 W5500 Socket 分配

| Socket | 用途 | 端口 |
|--------|------|------|
| 0 | 数据口（当前与 1 同口模式，基本不用） | 5001 |
| 1 | TCP Server Listen + 收发 | 5001 |
| 2 | UDP 组播发现 | 2468 |
| 3 | DHCP 客户端 | 68 |

配置见 `HARDWARE/W5500/network_cmd.h`、`w5500_dhcp.h`。

### 5.4 IP 获取（DHCP）

| 步骤 | 位置 |
|------|------|
| 默认开启 DHCP | `USE_DHCP = 1`（network_cmd.h / device.c） |
| 初始化 | `W5500_DHCP_Init()` → `WIZnet/dhcp.c` |
| 周期运行 | `DHCP_Client_Task()` in W5500_Task |
| 看门狗 | 开机约 50s 仍无 IP → 硬复位 W5500；之后每 10s 检测 |
| 成功后 | `UDP_Broadcast_Init()` + `Ph_Net_RebindOnIpChange()` |

串口切换：`netmode,dhcp,end` / `netmode,static,end`（cmd.c）

### 5.5 组播发现（给 Android 主机用）

- 地址：`236.2.3.6:2468`
- 周期：1 秒（IP 有效后）
- 载荷格式：`型号,SN,IP,控制端口,数据端口,协议地址,类型,预留`
- 实现：`Broadcast_Fill_Data()` in w5500_dhcp.c

## 6. 通信协议（与 Android Fsy 对齐）

### 6.1 帧格式

Modbus RTU over TCP：

```
[从机地址][功能码][数据...][CRC低][CRC高]
```

### 6.2 常用功能码

| 功能码 | 方向 | 用途 |
|--------|------|------|
| 0x03 / 0x13 | 主机读 / 从机应答 | 读寄存器 |
| 0x06 / 0x16 | 主机写 / 从机应答 | 写单寄存器 |
| 0x10 / 0x20 | 主机写 / 从机应答 | 写多寄存器 |
| **0x23** | **从机主动上传** | 实时数据心跳（约 950ms） |
| 0x25 | 从机主动上传 | 单寄存器事件上传 |

### 6.3 关键寄存器（节选）

完整定义：`dev_protocol/net_raw/net_raw_app.h`

| 地址 | 内容 |
|------|------|
| 1–16 | 剂量率、环境量、报警位、状态位 |
| 50–73 | 各类报警阈值 |
| 82 | 报警使能掩码（0x52 对应） |
| 121–123 | 设备地址、报警音量、屏/光控制（0x7A/0x7B） |
| 200+ | OTA 寄存器区 |

### 6.4 与 Android 主机关系

```
探头 RAD-I                         主机 Fsy (NetShield)
─────────────────────────────────────────────────────
UDP 236.2.3.6:2468 组播    →    FsyMulticastDiscovery.kt
TCP 5001 从机            ←    FsyTcpClient.kt 连接
0x23 主动上传              →    FsyTcpProtocol.kt 解析
写寄存器配置               ←    ProbeProtocolExt.kt / 设置页
```

## 7. 核心业务模块

### 7.1 盖革 / 剂量率

| 文件 | 职责 |
|------|------|
| `HARDWARE/GEIGER/geiger.c` | 计数、5 分钟累计、报警、写历史 |
| `HARDWARE/DOSE_RATE/dose_rate.c` | EWMA 滤波，支持真实/模拟/手动 CPS |
| `HARDWARE/beep/` | 声报警 |

### 7.2 环境传感器

`Env_Monitor_Task` 周期采集：

- BME280：温度、湿度、气压
- ENS160：CO2
- PM2.5
- PCF8563：RTC

采集后调用 `Net_Sync_SensorData_To_Registers()`，并按 `NET_ACTIVE_UPLOAD_PERIOD_MS`（约 950ms）调用 `Net_Active_Upload_Scheduled()`。

### 7.3 配置与历史数据

| 模块 | 文件 | 说明 |
|------|------|------|
| 设备配置 | `DATA_MANAGER/device_config.c` | SN、阈值、报警开关、亮度等，存外部 Flash |
| 5 分钟历史 | `DATA_MANAGER/hist_record_app.c` | 基于 `dm_core` 的环形 Flash 记录 |
| Flash 后端 | `DATA_MANAGER/dm_flash_backend.c` | QSPI W25Q 读写 |

API 迁移说明（2026 维护时注意）：

- 旧：`g_data_5min_mgr` / `DataManager_Init`
- 新：`HistRecord_Init()` / `HistRecord_Read()` / `HistRecord_GetManager()`

### 7.4 显示

- `LVGL_Task` → `LVGL/app/ui.c`
- LCD 驱动：`HARDWARE/LCD/lcd_rgb.c`

### 7.5 LoRa / CAN（备用链路）

- 与 TCP 共用寄存器表，优先级低于 TCP
- LoRa：`HARDWARE/LORA/`
- CAN：`dev_protocol` 中 `Ph_Can_*`（当前 `DEV_PROTOCOL_CAN = false`）

## 11. 已知架构特点 & 维护注意

1. **W5500 硬件 TCP**：没有 lwIP，不能按 socket API 文档想当然；TCP 状态由芯片维护。
2. **网络轮询集中在一个任务**：`W5500_Task` 负责 DHCP + 协议，一般不要在其他任务直接操作 W5500 SPI。
3. **SPI 无任务级互斥**：`iinchip_spi_enter` 已写但未全面接入；`Uart_Recv_Task` 发 `netmode` 时可能与 `W5500_Task` 竞态。
4. **默认 MAC 固定**：`CC:08:DC:11:11:11`；多机同网需改 MAC 或会 DHCP 冲突。
5. **DHCP 看门狗会硬复位芯片**：约 50s 无 IP 触发；慢网络环境可能和 DHCP 协商打架。
6. **DATA_MANAGER 曾重构**：遇到 `g_data_5min_mgr` 未定义，应改用 `HistRecord_*` API；Keil 需包含 `dm_core.c`、`hist_record_app.c` 等。

## 12. 与「成熟 RTOS 网络栈」的区别

| | RAD-I（现状） | lwIP / FreeRTOS+TCP |
|--|---------------|---------------------|
| TCP/IP 在哪 | W5500 芯片内 | MCU 软件实现 |
| 上层接口 | 自研 `Ph_Net_*` + Modbus | BSD socket / netconn |
| 资源占用 | MCU 省，SPI 通信 | RAM/Flash 较大 |
| 适用性 | 固定 Modbus 从机协议 | 通用 TCP/HTTP/MQTT |

当前选型对「固定协议从机 + LVGL + 盖革」是合理的；若要 MQTT/HTTPS 再评估是否换内置 MAC + lwIP。
