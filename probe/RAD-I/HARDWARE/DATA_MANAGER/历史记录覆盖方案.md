# 5 分钟历史记录覆盖方案

## 一、Flash 存储架构

### 1.1 扇区布局

```
外部 QSPI Flash（W25Q64JV：8MB）布局：

地址：0x00000000
┌─────────────────────────┐
│ 元数据扇区              │ 4KB（1 个扇区）
├─────────────────────────┤
│ 正式扇区 0              │ 4KB（主数据区）
│ 正式扇区 1              │ 4KB（主数据区）
│ ...                     │
│ 正式扇区 N-1            │ 4KB（主数据区）
├─────────────────────────┤
│ 缓存扇区 0              │ 4KB（与正式扇区一一对应）
│ 缓存扇区 1              │ 4KB
│ ...                     │
│ 缓存扇区 N-1            │ 4KB
├─────────────────────────┤
│ 临时扇区                │ 4KB（独立扇区，时间调整时用）
├─────────────────────────┤
│ 配置区（64KB）          │ Flash 末尾
└─────────────────────────┘

参数定义：
- DATA_5_MIN_MAX_RECORDS = 300（最大记录数）
- EXT_FLASH_DM_SLOTS_PER_SECTOR = 512（每扇区记录数）
- EXT_FLASH_DM_DATA_SECTOR_COUNT = 1（正式扇区数量）
- EXT_FLASH_DM_CACHE_SECTOR_COUNT = 1（缓存扇区数量）
- 临时扇区数量 = 1（独立扇区）
```

### 1.2 扇区类型说明

| 扇区类型 | 用途 | 数量 | 特性 |
|---------|------|------|------|
| **正式扇区** | 稳定数据存储 | N 个 | 环形存储，满后不主动擦除 |
| **缓存扇区** | 活动数据写入 | N 个 | 与正式扇区一一对应，新记录优先写入 |
| **临时扇区** | 时间调整缓冲 | 1 个 | 独立扇区，时间调整时临时使用 |

### 1.3 正常写入流程

```
原则：
1. 新记录始终写入缓存扇区
2. 缓存扇区满后，迁移到正式扇区
3. 正式扇区满后，循环覆盖最旧扇区

流程：
第 1 条 → 缓存扇区 0 的第 0 条
第 2 条 → 缓存扇区 0 的第 1 条
...
第 512 条 → 缓存扇区 0 满，触发迁移
  → 擦除正式扇区 0
  → 复制缓存扇区 0 到正式扇区 0
  → 擦除缓存扇区 0
  → 新记录写入缓存扇区 1 的第 0 条
...
第 N 条 → 缓存扇区 N-1 满
  → 擦除正式扇区 0（最旧）
  → 复制缓存扇区 N-1 到正式扇区 0
  → 擦除缓存扇区 N-1
  → 新记录写入缓存扇区 0 的第 0 条（循环）
```

## 二、时间调整覆盖方案

### 2.1 核心原则

```
1. 新记录始终优先写入缓存扇区
2. 时间调整时，只操作缓存扇区和临时扇区
3. 正式扇区的数据保持稳定，不轻易擦除
4. 读取时自动判断正式扇区 + 缓存扇区（或临时扇区）
5. 时间回调时，保留有效记录，覆盖无效记录
6. 时间调快时，恢复之前被隐藏的记录
```

### 2.2 时间回调流程（需要覆盖）

#### 场景 A：未满一轮，需要覆盖当前缓存扇区（使用独立扇区）

```
重要概念：
- 未满一轮 = 还有空白正式扇区
- 已写入的缓存扇区满后，数据迁移到正式扇区，缓存扇区被擦除
- 当前只有一个缓存扇区正在使用（活动写入）
- 有效记录数 = 已写入正式扇区的有效数 + 当前缓存扇区的有效数
- 时间回调需要覆盖**当前缓存扇区**时，使用独立扇区作为临时缓冲

初始状态：
- 正式扇区 0-1：已写满（2×512=1024 条，缓存扇区 0-1 已擦除）
- 正式扇区 2-3：空白（未使用）
- 缓存扇区 0-1：已擦除（数据已迁移到正式扇区）
- 缓存扇区 2：正在写入（第 80 条）
- 缓存扇区 3：空白
- 独立扇区：空白
- 总有效记录数：1024 + 80 = 1104 条
- 系统时间：18:00（时间戳 20000）

操作：时间回调到 12:00（时间戳 15000）
需求：缓存扇区 2 的前 19 条有效，从第 20 条开始覆盖

步骤 1：扫描缓存扇区 2
- 前 19 条：有效（时间戳≤15000）
- 后 61 条：无效（时间戳>15000）

步骤 2：处理独立扇区（关键！）
- 擦除独立扇区
- 读取缓存扇区 2 的前 19 条到 RAM
- 写入独立扇区的前 19 条
- 记录：独立扇区缓存的是"缓存扇区 2"的数据

步骤 3：更新元数据
- current_system_ts = 15000
- valid_count = 1024 + 19 = 1043 条
- formal_valid_count = 1024
- current_sector_type = TEMP（使用独立扇区）
- temp_write_next = 19
- temp_sector_cached_source = 2（缓存的是缓存扇区 2）
- 保存元数据

步骤 4：写入新记录
- 新记录写入独立扇区的第 20 条
- valid_count++

结果：
- 有效记录：1043 条 + 新写入的记录
- 当前写入：独立扇区的第 20 条
- 缓存扇区 2：保持原样（19 条有效 + 61 条无效，但不使用）
- 独立扇区：19 条有效记录 + 新记录

后续处理（独立扇区写满后）：
当独立扇区写满（第 512 条）：
1. 擦除正式扇区 2
2. 将独立扇区的 512 条复制到正式扇区 2
3. 擦除独立扇区
4. 擦除缓存扇区 2
5. 新记录写入缓存扇区 3 的第 0 条
6. 更新元数据
```

#### 场景 B：未满一轮，需要覆盖已完成的正式扇区（不使用独立扇区）

```
重要概念：
- 时间回调需要覆盖的是**已完成的正式扇区**（而非当前缓存扇区）
- 此时直接将正式扇区的有效记录复制到对应的缓存扇区
- **不需要使用独立扇区**

初始状态：
- 正式扇区 0-1：已写满（2×512=1024 条）
- 正式扇区 2-3：空白（未使用）
- 缓存扇区 0-1：已擦除（数据已迁移到正式扇区）
- 缓存扇区 2：正在写入（第 100 条）
- 缓存扇区 3：空白
- 独立扇区：空白
- 总有效记录数：1024 + 100 = 1124 条
- 系统时间：18:00（时间戳 20000）

操作：时间回调到 12:00（时间戳 15000）
需求：需要从**正式扇区 1**的第 32 条开始覆盖（前 31 条有效）

步骤 1：扫描正式扇区 1
- 前 31 条：有效（时间戳≤15000）
- 后 481 条：无效（时间戳>15000）

步骤 2：复制到缓存扇区（关键！）
- 擦除缓存扇区 1
- 读取正式扇区 1 的前 31 条到 RAM
- 写入缓存扇区 1 的前 31 条
- 更新：cache_write_next = 31

步骤 3：更新元数据
- current_system_ts = 15000
- valid_count = 512（正式扇区 0）+ 31（缓存扇区 1）= 543 条
  （注意：缓存扇区 2 的 100 条无效，因为时间戳>15000）
- formal_valid_count = 512（只有正式扇区 0）
- current_sector_type = CACHE
- current_sector_idx = 1（切换到缓存扇区 1）
- 保存元数据

步骤 4：写入新记录
- 新记录写入缓存扇区 1 的第 32 条
- valid_count++

结果：
- 有效记录：643 条 + 新写入的记录
- 当前写入：缓存扇区 1 的第 32 条
- 正式扇区 1：保持原样（逻辑上无效，但物理保留）
- 缓存扇区 2：100 条记录（逻辑上无效，但物理保留）
- 独立扇区：未使用（空白）

后续处理：
- 缓存扇区 1 写满后（第 512 条）：
  1. 擦除正式扇区 1
  2. 将缓存扇区 1 复制到正式扇区 1
  3. 擦除缓存扇区 1
  4. 新记录写入缓存扇区 2 的第 0 条
  5. 更新元数据
```

操作：时间回调到 12:00（时间戳 15000）
需求：缓存扇区 3 的前 99 条有效，从第 100 条开始覆盖

步骤 1：扫描缓存扇区 3
- 前 99 条：有效（时间戳≤15000）
- 后 401 条：无效（时间戳>15000）

- 写入独立扇区的前 99 条

- current_system_ts = 15000

步骤 4：写入新记录

结果：
- 有效记录：1635 条 + 新写入的记录

- 缓存扇区 3：保持原样（99 条有效 + 401 条无效，但不使用）
- 正式扇区 3：保持原样（前 99 条逻辑上无效，因为已复制到独立扇区）
- 独立扇区：99 条有效记录 + 新记录

后续处理（独立扇区写满后）：

1. 擦除正式扇区 0（最旧的扇区）
2. 将独立扇区的 512 条复制到正式扇区 0

4. 擦除缓存扇区 3
5. 新记录写入缓存扇区 0 的第 0 条（循环）
6. 更新元数据
```

### 2.3 时间调快流程（恢复记录）

#### 核心原则

```
1. 时间调快时，独立扇区的数据**直接丢弃**
2. 恢复使用原来的缓存扇区（如果缓存扇区的数据时间戳≤新系统时间）
3. 扫描所有扇区，计算新的有效记录数
4. 更新元数据，继续在原缓存扇区写入

关键：
- 独立扇区是临时缓冲，时间调快时不再需要
- 原来被"隐藏"的缓存扇区记录可能恢复有效
- 有效记录数 = 正式扇区有效数 + 缓存扇区有效数
```

- temp_sector_cached_source = 2

- 擦除独立扇区

步骤 3：更新元数据

```

## 三、读取策略

### 3.1 核心原则

```
1. 有效记录范围：
   - 总有效记录数 = valid_count
   - 正式扇区有效数 = formal_valid_count
   - 缓存扇区有效数 = valid_count - formal_valid_count

2. 读取第 K 条记录（逻辑索引，从 0 开始）：
   - 如果 K < formal_valid_count → 读正式扇区
   - 如果 K >= formal_valid_count → 读活动扇区（缓存扇区或临时扇区）

3. 正式扇区是环形存储：
   - 需要知道最旧的正式扇区索引（oldest_formal_sector）
   - 扇区索引 = (oldest_formal_sector + 扇区偏移) % 正式扇区总数

4. 缓存扇区/临时扇区：
   - 直接使用 current_sector_idx 或临时扇区
```

### 3.2 读取规则

```
读取第 K 条记录（逻辑索引，从 0 开始）：

步骤 1：判断 K 的范围
- 如果 K < formal_valid_count → 读正式扇区
- 否则 → 读活动扇区（缓存扇区或临时扇区）

步骤 2：计算物理位置

情况 A：读正式扇区（K < formal_valid_count）
  - sector_offset = K / SLOTS_PER_SECTOR
  - slot_index = K % SLOTS_PER_SECTOR
  - sector_index = (oldest_formal_sector + sector_offset) % FORMAL_SECTOR_COUNT
  - 读取正式扇区 sector_index 的第 slot_index 条

情况 B：读活动扇区（K >= formal_valid_count）
  - offset = K - formal_valid_count
  - 如果 current_sector_type == CACHE：
    - 读取缓存扇区 current_sector_idx 的第 offset 条
  - 如果 current_sector_type == TEMP：
    - 读取临时扇区的第 offset 条

步骤 3：读取数据并返回
```

## 四、元数据结构

### 4.1 元数据字段

```c
typedef struct {
    // 系统时间
    uint32_t current_system_ts;    // 当前系统时间的 Unix 时间戳
    
    // 有效记录计数
    uint16_t valid_count;          // 总有效记录数
    uint16_t formal_valid_count;   // 正式扇区有效记录数
    
    // 活动扇区写入位置
    uint16_t cache_write_next;     // 缓存扇区写入位置（下一条写入的索引）
    uint16_t temp_write_next;      // 临时扇区写入位置
    
    // 当前扇区状态
    uint8_t current_sector_type;   // 当前扇区类型：0=FORMAL, 1=CACHE, 2=TEMP
    uint8_t current_sector_idx;    // 当前扇区索引（0~N-1）
    
    // 临时扇区状态
    uint8_t temp_sector_active;    // 临时扇区是否激活：0=未使用，1=使用中
    
    // 保留字段
    uint8_t reserved;              // 保留（字节对齐）
    
    // 校验和
    uint32_t crc32;                // 元数据校验和
} DataManager_Meta_t;
```

### 4.2 扇区类型定义

```c
#define SECTOR_TYPE_FORMAL    0    // 正式扇区
#define SECTOR_TYPE_CACHE     1    // 缓存扇区
#define SECTOR_TYPE_TEMP      2    // 临时扇区
```

### 4.3 元数据保存时机

```
1. 修改系统时间后 → 立即保存
2. 活动扇区切换时 → 立即保存
3. 每写入 N 条记录后 → 定期保存（如每 10 条）
4. 系统空闲时 → 定期保存（防止掉电）
```

## 六、关键要点总结

### 6.1 核心原则

1. **新记录始终写入缓存扇区**（或临时扇区）
2. **缓存扇区满后，迁移到正式扇区**
3. **正式扇区的数据保持稳定**，不轻易擦除
4. **时间调整时，只操作缓存扇区和临时扇区**
5. **读取时自动判断正式扇区 + 活动扇区**
6. **时间调快时，自动恢复之前隐藏的记录**

### 6.2 时间回调处理

```
1. 扫描所有记录，确定有效范围
2. 计算有效记录数
3. 处理当前缓存扇区：
   - 有有效记录 → 保留并写回
   - 全部无效 → 清空
4. 如果当前缓存扇区全部无效且正在使用：
   - 启用临时扇区
   - 清空所有缓存扇区
5. 更新元数据
6. 继续写入新记录
```

### 6.3 时间调快处理

```
1. 扫描所有扇区
2. 恢复正式扇区的有效记录
3. 恢复缓存扇区的有效记录
4. 如果在临时扇区：
   - 迁移到缓存扇区
   - 清空临时扇区
5. 更新元数据
6. 继续写入
```

### 6.4 读取策略

```
1. 判断读取范围：
   - K < formal_valid_count → 读正式扇区
   - 否则 → 读活动扇区
2. 计算物理位置
3. 读取并返回
```

## 七、注意事项

### 7.1 Flash 擦除特性

```
1. Flash 擦除单位：扇区（4KB）
2. 擦除次数限制：约 10 万次
3. 写入特性：只能 0→1（不需要擦除）
4. 写入 1→0：必须先擦除整个扇区

优化策略：
- 减少不必要的擦除
- 优先使用 EMPTY 扇区
- 缓存扇区满后才擦除正式扇区
- 时间调整时不立即擦除
```

### 7.2 掉电保护

```
1. 元数据保存后立即写入 Flash
2. 关键操作前后保存元数据
3. 使用 CRC32 校验元数据完整性
4. 掉电后可从元数据恢复状态
```

### 7.3 磨损均衡

```
1. 记录每个扇区的擦除次数
2. 优先擦除次数少的扇区
3. 避免某些扇区过度磨损
```
