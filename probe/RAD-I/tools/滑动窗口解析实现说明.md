# 滑动窗口解析实现说明

## 更新内容

### 2026-04-08 - 实现 TCP/UDP 滑动窗口解析

#### 1. 问题背景

**原问题：**
- 网口模式（TCP/UDP）使用滑动窗口解析，但逻辑与串口模式不一致
- 变长帧（如 0x13 读多应答）解析不准确
- 没有正确处理 TCP 粘包问题

**需求：**
1. 网口模式使用串口模式的解析逻辑（不依赖 `\r\n` 分割）
2. 支持 TCP 粘包处理
3. 参考 C 代码的滑动窗口逻辑（`net_raw_protocol.c#L1163-1246`）

#### 2. 实现方案

**核心算法：** 滑动窗口 CRC 匹配模式

```python
def parse_and_display_registers(self, data: bytes):
    """
    解析并显示寄存器数值 - 滑动窗口模式
    核心思想：
      1. 从缓冲起始位置搜索所有可能的帧边界（最小 4 字节到最大帧长）
      2. 找到第一个 CRC 合法的帧即处理（避免过度匹配）
      3. 支持多帧累积处理，适应 TCP 流式特性
    """
```

**关键步骤：**

1. **跳过填充零**
   ```python
   while pos < n and data[pos] == 0:
       pos += 1
   ```

2. **滑动窗口搜索**
   ```python
   for try_len in range(4, maxtry + 1):
       chunk = data[pos:pos + try_len]
       if CRC16.verify(chunk):
           flen = try_len
           break  # 找到第一个合法帧即停止
   ```

3. **处理合法帧**
   - 解析功能码
   - 提取寄存器数据
   - 更新显示窗口

4. **跳过已处理帧**
   ```python
   pos += flen
   ```

#### 5. 与串口模式的对比

| 特性 | 串口模式 | TCP/UDP 模式（新） |
|------|---------|------------------|
| 数据分隔 | 按 `\r\n` 分割 | 滑动窗口查找 CRC |
| 帧边界 | 明确（\r\n） | 动态查找 |
| 解析核心 | `parse_frame()` | `parse_frame()` |
| 变长帧处理 | 依赖 `\r\n` | 滑动窗口 + byte_count |
| 粘包处理 | 不需要 | 滑动窗口自动处理 |
| 功能码支持 | 0x15/0x13/0x23 | 0x15/0x13/0x23/0x25 |

**关键差异：**
- 串口模式：依赖 `\r\n` 确定帧边界
- TCP/UDP 模式：滑动窗口查找 CRC 确定帧边界
- **解析逻辑一致**：都使用 `parse_frame()` 解析协议字段

#### 6. C 代码参考

实现逻辑完全参考 C 代码 `net_raw_protocol.c#L1163-1246`：

```c
// C 代码核心逻辑
uint16_t pos = 0;
while(pos + 4 <= n)
{
    // 跳过填充零
    while(pos < n && crt_xfer->recv[pos] == 0)
        pos++;
    
    // 滑动窗口搜索
    for(uint16_t try_len = 4; try_len <= maxtry; try_len++)
    {
        if(Net_Raw_FrameCrcOk(crt_xfer->recv + pos, try_len))
        {
            flen = try_len;
            break;  // 找到第一个合法帧即停止
        }
    }
    
    if(flen)
    {
        // 处理合法帧
        pos += flen;  // 跳过已处理帧
    }
    else
    {
        pos++;  // 无合法帧，前进 1 字节
    }
}
```

#### 7. 优势

1. **统一解析逻辑** - 串口和网口使用相同的 `parse_frame()` 函数
2. **正确处理粘包** - 滑动窗口自动处理 TCP 粘包
3. **支持变长帧** - 正确解析 0x13、0x23 等变长帧
4. **容错性强** - 即使数据流中有无效字节，也能通过滑动找到合法帧
5. **与 C 代码一致** - 逻辑完全参考固件代码，便于维护

#### 8. 注意事项

1. **最大帧长限制** - 当前设置为 256 字节，可根据需要调整
2. **性能考虑** - 滑动窗口在最坏情况下需要多次 CRC 计算
3. **帧边界模糊** - 如果数据流中恰好有 CRC 巧合的字节，可能误判（但概率极低）

#### 9. 后续优化建议

1. **添加帧缓存** - 对于不完整的帧，缓存到下次接收
2. **优化 CRC 计算** - 使用查表法加速 CRC 校验
3. **添加调试输出** - 在开发模式下显示滑动窗口过程
