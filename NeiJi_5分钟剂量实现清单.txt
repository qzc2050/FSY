================================================================================
NeiJi 5 分钟剂量实现清单
语义：reg34 = 5 分钟累计剂量 D5（μSv×100），由 10 个 30 秒块 D30 相加
reg1 仍为 1s 瞬时剂量率（μSv/h×100），与 5min 账本分离
================================================================================

【Phase 1 范围 — 当前要做】

  reg30~34：设备每 5 分钟上传的「当前这一窗」实时五分钟值（非历史补拉）
    - 0x23 start=0x001E，12B = data_time[8] + D5(μSv×100)
    - 0x03 读 reg30~35 = 最近一次 5min 快照（与最后一帧 0x23 一致）
    - App 收到后按设备时间入库，日累计 = Σ 当天 D5

  时间同步（App → 设备 reg94）：
    - 收到 5min 0x23（或读到 reg94）时，若 |设备时间 − App 时间| > 5 分钟
      → 立即写 reg94 同步（不等 6h 周期）
    - 样本时间戳一律用帧内 data_time，不用手机收到时刻

  Phase 1 不做：
    - 文档现有 reg108~112 历史区间查询（下一步另定寄存器，重新设计）
    - 主机向设备「拉历史五分钟」的协议与 UI

【Phase 2 — 下一步】

  - 历史五分钟值：重新定寄存器（不复用现表 108~112 亦可）
  - 设备 Flash 288 条环（12/h×24h）及历史上传状态机
  - App 历史补拉 / 断网补数据

================================================================================

【目标数据流 — Phase 1】

  盖革 100ms 计数增量
       ↓ 积分（本底/死时间/灵敏度，与 Geiger_Dose_Calculate 一致）
  dose_30s_acc（μSv）
       ↓ 每 30s 边界
  D30 → 累加到 dose_5min_acc；dose_30s_acc = 0
       ↓ 每 5min 边界（建议对齐 RTC :00/:05/:10…）
  D5 = dose_5min_acc
       ├→ reg30~34 镜像（实时快照）
       └→ 0x23 主动上传（start=0x001E，12 字节）
  dose_5min_acc = 0

  App：收到 0x23(0x001E)
       → 用 data_time 作 recordedAt
       → 若 |设备−App|>5min 则 reg94 对时
       → 存 D5(μSv) → 日累计 = Σ 当天 D5

八、测试用例
================================================================================

[ ] 8.1 单元（固件）
      - D30×10 累加 = D5（浮点误差 < 0.01 μSv）
      - dose_30s_acc 每 30s 清零
      - dose_5min_acc 每 5min 清零

[ ] 8.2 恒定 CPS
      - 已知 CPS + sensitivity，预期 D5 ≈ CPS×300/(sens×60) μSv（与公式推导一致）

[ ] 8.3 协议
      - Wireshark/串口：0x23 reg=0x001E，12 字节，CRC 正确
      - 0x03 读 reg30~35 与最后一帧 0x23 一致

[ ] 8.4 App 时间
      - 设备时间比 App 快 6min → 收到 5min 后应触发 reg94
      - 设备时间比 App 慢 6min → 同上
      - 偏差 2min → 不触发（<5min 阈值）

[ ] 8.5 App 日累计
      - 收到 3 条 5min（各 0.10 μSv，设备日期同一天）→ 日累计 0.30 μSv
      - 不再从 reg1 实时率插值

[ ] 8.6 边界
      - RTC 未设置：不上传 reg30/0x23，积分可继续
